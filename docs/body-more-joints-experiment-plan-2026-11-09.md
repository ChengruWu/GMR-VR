# GMR Body：增加人体关节信息的离线实验计划

日期：2026-11-09  
范围：GMR-VR；输入为 `experiment_data/body_session_20261109_1433/`（相对于 GMR-VR 仓库根目录）；先离线、再仿真。目标是改善 Luna 对人体动作的拟合，保留现有 GMR/IK 路径，以对照实验决定哪些额外信息有用，而不是以任务点数量作为目标。

## 1. 现状与证据

- PICO 帧含 24 个关节，当前检查全部关节；17 个经命名和坐标转换，当前 `human_scale_table` 和 `ik_match_table1` 仅使用 9 个：骨盆、胸、头、双肩、双肘、双腕。左右髋、膝、踝、脚虽完成转换，未作为 IK 任务。`spine1`、`spine2`、`neck`、双 collar、双 hand 目前也不在 17 项映射中。
- 求解器是 GMR 的 Mink 帧任务加权 IK；实时实验采用首次有效帧相对对齐、`relative_position_scale=0.8`，以每周期机器人反馈为初值，底盘、轮和夹爪自由度固定；夹爪输出由扳机单独产生。机器人模型的支撑链是单条链，不是左右两条人腿。
- 本次文件含 443 个控制周期、442 个不同来源帧、约 24.531 秒，414 次 command、29 次 idle；按 `(session_id, frame_seq)` 关联。反馈采集在该周期发布前，头显 Body 与手柄异步，不能视为同一物理时刻。
- 在控制周期关联帧中，左右 wrist 在 XR Y 轴变化范围约 0.699/0.747 m；pelvis、head、spine3 分别约 0.014/0.010/0.011 m。它适合先比较双臂及稳定站姿，不能据此验收下蹲、弯腰、转身或行走。XR `Local` 轴和追踪语义仍须验证。
- 历史使用的 wheel SHA-256：`4c4d94252991130779daf313f9b2425a96740744c876929d5af0c7e9acaa6a8a`。当前仓库代码与当时 wheel 不应假设完全相同。已有 `scripts/render_body_comparison.py` 从当前 Python 环境导入 `gmr_body`，可能加载已安装 wheel 而不是当前源码；开展实验前必须确认 `gmr_body.__file__`、资源文件和求解器来源，不能把它当成自动验证新代码的工具。

## 2. 固定基线与可重复回放

1. 保存数据和版本清单：验证录制 README 中两份 JSONL 的 SHA-256；记录 GMR-VR commit、dirty diff、EVA 契约版本、Python/依赖、导入模块路径及配置内容；本次验证录制及复现资料已随仓库提交；新增人体记录和实验结果仍留在忽略目录。
2. 实现参数化离线回放：按 `(session_id, frame_seq)` 精确匹配，保留重复控制周期和原始顺序；记录匹配数、缺失数、追踪有效性、握把状态、时间范围和各周期结果。处理 `idle`/重复样本与初始化，不能伪造数据补帧。
3. 基线 A 采用本次 9 点、0.8 相对对齐、底盘关闭和历史条件；相同控制周期统一使用记录的反馈作为初值（开环条件回放）。先核对 414 个命令与记录目标的误差，并报告差异及代码/wheel 版本，不把数值一致当成动作正确的证明。保持 24 点有效性门槛、限位和安全开关不变。
4. 所有实验加载明确指定的源码及资源，不覆盖历史 wheel 或默认配置；在 `work_dirs/` 分目录保存机器可读配置、每帧目标/状态、时间和指标，并生成 H.264 对比视频。基线先验证，失败则排查来源后再比较。

## 3. 逐项实验：先使用 GMR 任务

所有候选默认关闭，使用独立配置和同一录制、同一初始参考、同一采样及反馈；每次只改变一类任务，权重从 0（应与基线一致）逐步增加，记录每种权重和偏移。保持手腕任务等原始约束作为共同指标。

### A. 多点躯干任务（第一优先）

- 将 PICO `spine1`、`spine2` 加入输入命名与归一化，检查每一帧坐标/姿态质量和参考姿态；核对它们在人体上的真实语义，不假定它们等同机器人关节。
- 检查 `luna_full.xml` 中 `Gento Luna_Leg_J1_Link` 至 `J6_Link` 的世界位置、局部坐标和运动范围；选可动且可解释的中间 body 作为候选。分别尝试 `spine1 → 一个支撑链中间 body` 和 `spine2 → 另一个中间 body` 的低权重位置/姿态任务，先单独、再联合。具体 body、轴、权重和偏移以可视化与初始姿态检查决定，不预设解剖一一对应。
- 扩展命名表、`human_scale_table`、任务表及首帧相对参考路径；核对 `offset_human_data` 要求每个进入 scale table 的名称都有位置和旋转 offset。任务表以机器人 body 为键、内部以人体名称索引任务，避免多个任务复用同一名称造成覆盖；本次不启用第二套任务表。
- 首先验证这段数据中的双臂跟随是否退化、站姿是否抖动；仅凭该数据不能判定弯腰效果。再用专门录制的弯腰、侧倾、转身序列检验躯干目标。

### B. 上肢额外信息（第二优先）

- 检查双 collar、双 hand 的相对位置、方向和连续性；`hand` 与 `wrist` 可能高度相关。先做离线质量与消融检查，再决定是否为相应的机器人肩部或末端增加低权重任务；如果缺少独立可对应 body，探索用它们改善原有目标，而不是强行重复同一个帧任务。
- 对比肘部轨迹、腕部目标误差、手部姿态和抖动。特别核对首帧偏移、左右方向和数据时序；不把额外 `hand` 点当作夹爪开合信号。

### C. 人体腿部与下蹲（后续单独实验）

- 先采集站立、弯腰、对称下蹲、起身、单脚变化等带标注数据。比较 pelvis、双髋、双膝、双踝与双脚的相对运动、稳定性和不同姿态的可区分性。
- 先评估是否能为 Luna 支撑链定义有物理意义的 GMR 帧目标；没有左右机器人腿时，不直接将左右膝映射到同一个机器人“膝”。如必须先从人体点构造相对高度或动作意图，再将该目标交给 GMR，则将此作为独立方案，与直接任务明确区分。
- 不启用底盘移动，不把脚点误认为底盘速度指令；目标先受模型可达范围约束并只在离线/仿真中验证。

## 4. 评价和实验准入

- 分开报告两类指标：①原有共同任务的末端位置误差（m）、姿态误差（度）、肘部位置误差；②候选新增任务自身残差。不能只报告加入任务后其自身残差下降，也不能把人体与不同形态机器人世界坐标的直接距离当作唯一真值。说明坐标系、首帧对齐和姿态偏移。
- 按左右手分别比较相对初始姿态的位移曲线、幅度比、相关性及对应时间段；接近静止时不计算不稳定的幅度比。同步展示人体、基线、候选机器人，标注本周期状态与相机。
- 同时报告机器人关节位置/增量、限位余量和触限次数、输出不连续与速度/加速度代理指标、IK 求解时长 p50/p95/max、idle/rejected/reset 数；明确定义采样方式。回放只是运动学分析，不等同闭环跟踪、碰撞或物理安全验证。
- 每个候选需保证相同输入和有效样本，零权重与基线一致；不能引入新的非有限值、限位违反或未解释的拒绝。用双臂指标和标注片段进行逐项对照，列出改善和退化；阈值先由基线噪声/重复运行分布和实际任务需求确定，并在评估候选前固定。没有足够姿态覆盖时结论记为“证据不足”，不宣布优于基线。
- 对表现较好的候选，在独立 MuJoCo 木偶模式做闭环仿真对照：分别运行基线与候选，各用自身仿真反馈，而非共同使用记录反馈。记录两次初始状态、轨迹和频率；再评估跟随与碰撞。开环条件回放只隔离求解器差异，不能预测闭环轨迹。

## 5. 交付顺序

1. 数据清点与基线复现报告，明确历史 wheel 和源码差异。
2. 参数化回放、逐帧指标和 H.264 对照视频；验证零权重回归与重复帧处理。
3. 多点躯干单项/联合消融；用本次数据排除双臂退化，再使用补充录制验证弯腰。
4. 上肢额外点质量评估和必要的消融；下蹲数据和方案另行评估。
5. 选择证据支持的配置进入独立仿真，保留现有默认行为及可回滚基线；结果、参数、限制记录到仓库文档，新增个人数据与生成物留在忽略目录。

初期不修改真实机器人控制路径。当前录制、模型映射和单姿态对齐均未证明真实设备追踪精度、全动作空间、碰撞或硬件运行安全。
